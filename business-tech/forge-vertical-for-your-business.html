// Start with a real example

People used to send me photos of smashed cars asking for quotes. Each assessment took an hour or more — examining the photos, pricing the panels, estimating labour, checking for write-off thresholds. It was a manual process that happened dozens of times a week and consumed time that could have been spent on actual repairs.

So I built something. Upload the photos, and the system assesses the damage, itemises the repair costs, and flags whether the vehicle is likely a write-off. What took an hour takes about a minute. Aurora Repair is live and running on Gemini 2.5 Flash on Google Cloud Platform.

That is the starting point for everything Forge Vertical builds. A real problem. A system that solves it. Infrastructure that runs reliably without requiring someone to babysit it. Not a template with your logo on it. Not a WordPress site that breaks when a plugin updates. A real deployment.

The best advice for any business considering a technology investment is the same advice for anyone learning to build: start with a problem you actually have. You know the friction intimately. Why infrastructure decisions matter more than most businesses realise

// Chapter 02 — The decision that determines everything else

Most businesses approach digital projects by asking "what should this look like?" The more important question is "what should this run on?" The infrastructure decision — which database, which hosting, which authentication system, which payment provider — determines the running cost, the maintenance burden, the security posture, and the ability to change anything in the future.

A WordPress site on shared hosting looks identical to a custom-coded site on Cloudflare from the outside. Inside, one requires constant plugin updates, breaks when themes conflict, stores passwords in a database that shares a server with fifty other sites, and cannot be extended without adding more plugins. The other has none of those problems because the infrastructure was chosen deliberately before the first line was written.

The cheapest website is not the one with the lowest quote. It is the one that does not require R5,000 in emergency fixes eighteen months after launch because a plugin broke the checkout.

The same logic applies at every scale. A SaaS platform built on a low-code tool costs less upfront and more forever — in subscription fees, in feature limitations, in the inability to build the thing you actually need when your requirements evolve. A custom build on Firebase costs more upfront and runs at R800–R2,500 per month in hosting indefinitely, with no per-seat fees, no feature gates, and no dependency on the tool provider's roadmap.
